# 我们的阶段结果与初版Skill

## 一句话结论

偏好收集已足够支撑首版规范；下一步的核心是检验这些规则能否在真实任务中稳定产出正确、清晰、可编辑的图，而不是继续增加参考图数量。

## 已获得的结果

四批40条展示评价：24好、10一般、6差。它们不是40个去重的独立图，也不是生成结果的成功率。

已确认：浅色论文风；40式机制对照优先；31式主干+展开是标准备选；33式功能分块和34式直观机制保留；23式参数区可选；可以一次输出多个结构不同的实际成图。

仍是假设：层级化机制细节优于过度简化；对照的价值来自结构差异可见而非并排本身。没有证据把对36/37的差评扩展为对整个多模态类别的否定。

## 初版组成

短主Skill + 14条分证据等级的规则 + 4种结构配方 + 事实契约与反馈模板 + 40条原始标签 + 迭代计划。主Skill只加载当次需要的参考，不把全部材料塞入每次执行。

架构：事实与来源 → 图的语义契约 → 配方路由 → 可编辑HTML/SVG → 技术与布局验收 → 嵌入既有PPT流程。

默认交一个推荐方案；确有取舍或明确要求时通常生成三个实质不同的图。候选共享事实，不只换颜色。

## 迭代顺序

1. 补齐40/31/33/34最小原图锚点及溯源，复用已给评价。
2. 用一个有基线和改进的真实任务输出三种成图，验证推荐、选择、局部修改闭环。
3. 用四配方做冒烟回归，检查每种组织策略可执行。
4. 固定5篇新论文、每篇2题；3篇开发、2篇留出。相同预算比较旧流程与新规则的Top-1。
5. 单独比较默认首选与三选一，避免将额外采样收益误计为规则收益。
6. 在NPU推理业务图上迁移验证，再接入 `huawei-html-ppt`。

用户反馈减到“选哪张、是否可用、最大一个问题”。每轮只针对一两个明确失败修改规则，并保留旧正例回归。

## 当前交付边界

本包完成的是规范整理与数据一致性检查。没有附40张原图，没有生成能力测试结果，也没有安装或合入目标仓库。第五批参考图不是当前推进的前置条件；后续按覆盖缺口补图。
