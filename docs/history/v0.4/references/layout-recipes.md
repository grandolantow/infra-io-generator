# 四种结构配方

本文件是内容组织配方，不是从原图坐标复制出的模板。原图资产尚未归档。

## A — 40式：机制对照（默认优先）

**触发**：存在真实、可核实的基线与方案差异，例如依赖路径、信息混合、状态更新或计算布局变化。

**组织**：用一致抽象粒度并排或对齐呈现方案；相同结构保持位置/命名/颜色一致；变化集中高亮；仅在必要处局部放大。

**必须保留**：共同输入输出、共享结构、关键连接、差异的技术含义。一句结论说明为什么这些变化重要。

**不要做**：为凑三栏虚构第二个改进；将不同层次的对象强行并排；用大面积高亮代替清晰连线；为了接近样图而添加不真实的跨层边。

**候选变化**：相同事实可改为“基线/改进并列 + 下方局部展开”，或“共享主干 + 变化区域展开”。变化的是讲解结构，不是事实。

## B — 31式：主干 + 关键模块展开

**触发**：任务以完整模型架构或创新模块在主干中的位置为主；没有必要做多方案对照。

**组织**：全局主干占一个区域；一至几个关键模块在相邻区域展开。展开关系用一致标题、边框或连接明确标示。

**必须保留**：主干方向、重复层、关键残差，以及展开模块真实的输入输出。

**不要做**：把所有Linear/Norm/Activation均等展开；失去全局上下文；只列模块名称但不表达关系。

**参数**：重要维度、Top-k等就近标注；需要集中讨论资源配置时才启用23式参数侧栏。

## C — 33式：功能分块 + 分支汇合

**触发**：并行/混合模块、门控组合或多个职责区之间的关系是重点。

**组织**：按功能区而非按固定数量分块；区内保留必要计算，区间显示真实流向。先读主路径，再读分支。

**必须保留**：各分支输入来源、独立运算、汇合方式及输出；加和/拼接/门控不可混同。

**不要做**：为了版面整齐把串行伪装成并行；区间只连一根含义不清的箭头；过度分块导致读者找不到主线。

## D — 34式：直观机制与状态演化

**触发**：记忆读写、状态保留、反馈或信息返回关系比层堆叠更重要。

**组织**：用稳定区域表示持久对象，用明确边表达读、更新、写回及当前输出；时间或阶段变化需要显式标注。

**必须保留**：状态在何处、谁更新、什么时候可见、哪些路径影响当前输出。

**不要做**：用拟人或装饰插图代替技术关系；把反馈环误画成同一时刻无限循环；用直观隐喻改变实际机制。

## 多方案的共同约束

先冻结事实与任务范围，再选不同配方。相同事实必须覆盖；额外解释或省略须显式标记，不能把少画内容的方案与完整方案混为纯布局对比。

默认一个推荐版本；要求多方案时通常三个实图。已知参考布局或小修不强制扩展候选。

推荐排序在用户评价前固定。记录默认首选和“用户从多个中选中”的结果，不将二者混为同一质量指标。
