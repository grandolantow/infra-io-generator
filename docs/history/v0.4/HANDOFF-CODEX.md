# Codex实施交接

## 目标

把本规范落为一个能真实生成可编辑技术架构图的子Skill。优先跑通一题，而不是扩建素材库或开发通用绘图平台。

## 必须先做

读取 `SKILL.md`、规则、配方与目标仓库当前实现。确认现有HTML/SVG、页面数据模型、字体和导出链路。不要假定 `huawei-html-ppt` 的目录、函数或安装方式；本规范未检查它的当前代码。

如找到旧的24条规则包，先做来源与内容比对，再决定复用/替换。不能直接假定它已安装或有效。

## 第一轮实现范围

1. 从一个有完整来源的机制对照任务提取并冻结事实契约。
2. 按A/B/C或D做三个实际SVG，不得仅生成文字方案。
3. 生成自包含HTML，能切换候选，显示推荐项与来源。
4. 保留SVG可编辑文字/模块/箭头及共享语义源。
5. 做技术与布局验收，记录实际执行和未执行的检查。
6. 用户选定后，验证一次局部修改不会破坏其他区域。

以上即最小可用闭环。首轮不必实现PPTX、draw.io、自动案例检索、图数据库或多Agent协调。

## 约束

- 默认浅色；40式优先，但没有真实基线不做伪对照。
- 主干展开、分块、直观机制按内容路由。
- 参数侧栏可选，不把任何参考图的全部元素都复制进新图。
- 候选事实一致、任务范围一致、画布一致，避免删信息后伪装成布局更好。
- 不要求用户再做每轮十张原图打标。
- 外部原图须保留出处；未获取原图不得填写核验完成。
- 不为截图观感牺牲HTML/SVG可编辑性，不把截图作为唯一成品。

## 完成回报

回报实际新增/修改文件、可打开入口、通过的检查、未完成的检查、关键失败与推荐候选。格式检查和冒烟测试不得被表述为已证明优于旧Skill。

后续按 `references/iteration-plan.md` 固定任务和预算，做Top-1对照及单独的Best-of-3评测。
