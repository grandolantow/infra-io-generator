# 技术架构图

执行版本：v0.9.7（源码交付与任意画布渲染），Attention Residuals 原图布局校准。默认沿用用户认可的「清彩论文」浅底配色（paper-clear），可选「素雅灰蓝」（blue-neutral）；仅指定模板或显式配色时覆盖默认，不因置入PPT自动换色；默认用 draw.io 保留结构母版，Inkscape 做视觉精修；复杂公式或论文 LaTeX 集成时使用 TikZ。用户认为此前 Inkscape 版更好看，要求三版都向原图靠拢；不要预设某一工具一定更美。ELK、Penrose 暂缓扩展。Attention Residuals 校准及 DeepSeek-V2 / Hymba / Titans 三类已知参考迁移均不等于独立留出泛化。

## 先建立事实

从论文、官方代码或用户给定版本核对范围、受众和图的核心结论。固定来源版本与具体公式、算法或图号。事实未知时标记，不补造参数、基线或依赖。

按 `references/spec-contract.md` 写事实 JSON。区分：
- 必须在图上看见的事实；
- 放在页脚的适用范围与保证；
- 当前省略的内容及理由。

记录所有节点、实际边、汇合运算与关键 detail。只把事实塞入 SVG metadata 不算表达完成。数学限定、时间边界或概率保证需要读者理解时，必须成为可见文字或路径。

## 选择表达结构

先独立设计图，再适配容器。模型架构主干默认优先竖向展开，画布随层次深度和连线需要调整；不因最终用于PPT就默认1600×900或16:9。右侧机制展开为可选项，只有提升理解时才添加，不为填满横向空间而加说明框。单条竖向主干本身可以成为完整交付。机制对照、并行分支等需要横向阅读时仍按实际关系选择比例，不机械地把所有图改成长条。


按需读取 `references/layout-recipes.md`，优先迁移第40张 Attention Residuals 的共同结构对齐与机制差异显现方式，不规定栏数。保留第31张 DeepSeek-V2 的主干与展开、第33张 Hymba 的功能分块、第34张 Titans 的直观状态机制。

- 对照：存在真实共有输入输出、基线与改动时，对齐关系并突出变化。
- 主干与展开：显示整个机制的位置和关键子图；展开区与对应节点必须能对应，不能把旧方案冒称新方案主干。
- 功能分块：按真实职责和汇合关系分区，不把串行改成并行。
- 状态机制：先放旧状态与本步输入，再表达本步读出、新状态写回；下一时间步回边必须绕外部且明确标时序。区分本步的状态计算依赖与跨步反馈：本步写状态用 `state_write` 并参与拓扑排序；`state_update` 只用于已确认的下一步／下一迭代反馈。R3曾混用两者，导致SSD的②→③依赖被误排；此题保存为失败回归，不得标已解决。

默认一个推荐版本。用户要求多方案时提供三个有实质组织差别的成图。仅改栏宽、颜色、圆角、方向，不算三个结构方案。所有候选保留同一组必要事实。

## 执行原生绘图

先读 `references/golden-backends.md`，分清语义、模板与引擎各自贡献。做原图对照或三后端一致性校准时，读取 `references/golden-routing-v0.9.md`，使用 `assets/golden-refined/build.py` 的同事实、同布局场景；避免三个后端各自猜坐标。该样例只适用于四子层 S=2，不是任意模型编译器。普通任务按实际信息组织选结构，不强制共享同一版式。

1. 写语义清单：共有主干、原始输出、聚合输入、运算符、张量、区域、局部展开与边的实际端点。复杂聚合先列逐点候选集合。为对象设置稳定 ID。
2. 写架构模板：共享行列、节点尺度、入射端口、历史通道、分区边界与注释留白。优先相对约束和公共锚点；不要让公共线隐藏不同候选来源。
3. 生成原生 `.drawio` XML。用独立 cell 表达模块、圆形运算、张量片、标签和区域；边用 source/target 连接真实对象。不能将整图 SVG/PNG 嵌成一个对象后称原生可编辑。
4. 在实际 draw.io 引擎中导入、渲染与导出。按 `scripts/drawio_runtime/RUNTIME.md` 准备 Chrome、Playwright 和核对过的官方 Graph bundle，运行 `export.mjs` 获得 SVG/PNG 与运行记录。运行时缺失时注明，不能手写 SVG 替代后宣称已运行 draw.io。
5. 交付原生源、SVG、PNG、源码、事实与评测。HTML 内嵌图形或图片，无脚本也能看图；不要依赖远程 fetch、CDN 或未带齐的相对文件。先按图自身比例验收；需要嵌入PPT时，再按 `references/html-ppt-integration.md` 单独验收页面适配，不能反向挤压原图。

可复现原生样例在 `assets/golden-attnres/`，先读其中 `README.md`。它是四子层、S=2 的专用模板；事实 JSON 用于来源与核验，替换 JSON 不会自动生成其他模型。不要称其通用语义编译器。

原图布局修订的推荐样例为 `assets/golden-refined/`。运行 `python /path/to/skill/assets/golden-refined/build.py --out ./attnres-refined` 生成共享 scene、原生 draw.io、SVG 与 TeX；输出只写任务目录。运行 `verify.py ./attnres-refined` 校验语义端点和正交路径；实际后端导出后再验收。

旧 `scripts/render.py` 及 compare/backbone/mechanism 通用排布只用于拓扑草稿。前轮已显示其对复杂论文图的表达不足，不再作为生产默认。先闭环当前 golden，不通过扩充题库代替成图修复。

## 后端分工与主版本管理

遵循用户确认的默认分工：draw.io 管结构，Inkscape 管视觉精修，TikZ 按需承担复杂公式与 LaTeX 集成。具体交接规则见 `references/golden-backends.md`。

- 在 draw.io 母版中维护模块、数据流、功能分区、残差连接和稳定 ID；结构或技术事实变化先改母版及事实记录。
- 从已核验母版导出 SVG，在 Inkscape 中精修曲线、转角、间距、对齐和文字位置；保持语义端点不变，交付可编辑 SVG。
- 仅在复杂公式、论文 LaTeX 集成或用户明确要求时生成 TikZ；不默认每题制作三个后端版本。
- 标明结构母版与当前展示版本。三者不自动双向同步；母版变更后重新导出并复核精修，禁止旧 SVG 或 TeX 冒充最新版本。

## 按用途配置配色

先读 `references/palette-config.md`。在事实与布局之外保存 `target`（ppt/paper）、`palette`（auto 或预设名）和可选自定义覆盖；顺序为：显式颜色覆盖 > 显式 palette > target 默认。不要为换色改技术事实、节点 ID 或布局。

运行 `scripts/resolve_palette.py` 生成统一颜色配置；原生绘图与导出都用同一配置。默认 `paper-clear`（清彩论文），保留浅蓝、浅绿、淡黄、淡紫等功能色；可选 `blue-neutral`（素雅灰蓝），用低饱和灰蓝和浅灰保持分区。`huawei-plain` 保留为明确指定模板时使用的白灰红预设。配色选择独立于论文/PPT用途，用户明确选择始终优先。

已存在的图只能通过显式对象角色或源色映射应用颜色，不能按相似颜色推断语义。配色解析器和适配器不替代 draw.io 实际渲染，也不代表通用语义编译器。若未执行某后端渲染，仍标未测。功能框标签和技术术语用英文，图中短注释和箭头说明用英文，可独立阅读的长段说明用中文；不要因为选择配色改变语言。

## 实际渲染与修复

先查技术与可见事实，再查几何，最后查表达和偏好。

- 检查真实箭头端点与来源；共享线段、交叉点和白底标签可能改变读者理解。路径存在不等于路径可辨。
- 检查主路径、支路和控制／状态边。为分支配置不同端口；下一时刻和本步读写不得混排成同一步循环。
- 在最终页面内容区查看文字、关键公式、箭头与汇合。使用主体正常字号；空间不足时调整分区或拆层，不无限缩字。
- 查看参考原图时比较信息组织、运算可见性和路径，不以像素相似度评价。
- 区分字符估算、Inkscape 几何实测和浏览器 DOM 实测；没有运行的检查必须标 `not_run`。
- 检查局部修改：改标签后重生成，相关内容更新，无关稳定 ID 不漂移。实际拖动一个节点，检查附着边跟随、无关对象不动、ID/端点保留；没做过操作就标未测。
- 分别记录原生源可编辑、SVG text/foreignObject/image、GUI拖拽和PDF实际页面。官方Graph runtime不等于完整EditorUi/Desktop；PPT插入也需另测。不要将字形轮廓称SVG文字可编辑。
- 把实际引擎渲染后的连接折点也纳入正交检查；源路径是直角不保证引擎没有将端点投影成斜线。检测框线、虚线、引线对标签的遮挡，而非只查实心模块。

plain 导出不能依赖 `whiteSpace=wrap` 自动分行；主动换行并实测文字边界。检查非端点计算模块是否被数据边穿越、产生假依赖。圆滑转角必须在实际导出路径中可见，不能仅用 `stroke-linejoin=round` 冒充路径圆弧。换版式后重绑事实对象 ID。

记录每个候选为：技术错误／需要重构／需要局部修改／agent自检通过。只有用户反馈才可标用户认可。几何零告警不得改写成总体质量通过。
