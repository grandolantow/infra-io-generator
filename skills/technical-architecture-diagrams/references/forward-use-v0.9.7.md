# 独立上下文复现记录与规则补充

## 实际任务

在不提供此前 MiniMax 成图、坐标或生成器的情况下，只给固定技术事实、配置/代码快照与 Skill，独立制作竖向模型主干、MSA 与 MoE 机制图，分别生成清彩论文和素雅灰蓝。环境已提供依赖路径，因此不是干净机器安装测试。相同模型和相同事实的重建，不是独立留出论文泛化。

## 首版失败

首版实际 Graph 成图后保留了原生源与 QA。发现长行文字超框、注释与连线/区域边界交叠，以及 token 数据线穿过 MoE bias 框导致技术误读。外部图面复核还指出 MSA 长标签与残差尖角问题。首版标为需要修订，不能把修订后的结果回算成首版一次通过。

一次布局修订后，两种配色共六张图完成 Graph 与 Inkscape 导出。检查包括原生端点、残差来源、shared 分支绕过 routed 混合/缩放、颜色以外结构不变、三张清彩图的鼠标拖动与附着边跟随，以及离线 HTML 的 CSS 配色切换。部分算法事实依据固定输入底稿，未独立读取未提供的完整论文或后端 kernel；不能扩大为完整来源复核。

## 迁移规则

1. plain 模式不能依赖 `whiteSpace=wrap` 自动换行。主动给长标签分行，实测文字边界；不以不断缩字兜底。
2. 非端点计算模块不得成为其他数据边的穿越通道；区域容器边界与计算节点要区别处理。除检查 source/target，还要看中途是否产生假依赖。
3. 路径圆滑转角要在实际导出中可见。`stroke-linejoin=round` 只修线条接缝，不等于给直角路线加入圆弧。
4. 更换版式后重新绑定必要事实的可见对象 ID，不能继续引用旧版对象。
5. 执行通过与视觉语言分别评价。该次重建仍偏流程框式；张量集合、共享选择与机制差异的直观表现尚未达到用户 golden，不能标用户认可。

该记录验证了有依赖环境下的可执行性与修订闭环，暴露了首版布局稳定性的不足。下一轮应优先检查无需外部反馈时能否自行拦住上述错误，而非增加参考图数量。
